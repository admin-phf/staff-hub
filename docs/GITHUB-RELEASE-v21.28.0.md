# Staff Hub v21.28.0 — UI/UX refinement package (Tasks 1–11): sticky full-width RUN strip, clickable stage pills, one shared stylesheet (20 Oct 2026 12:30 AEDT)

**Summary:** v21.28.0 — implements the Package 3 UI/UX brief across Build POS Master Databases and POS New Product Check Clean: the RUN strip moves above both columns, full width and sticky; its numbered stage pills become real buttons; the rail's Drop-All rows no longer wrap one letter per line and use READY / UPDATED / REVIEW / INCOMPATIBLE; generated-file rows are one compact line; badges follow one colour system; the merge tool's two sidebar explanations are removed and each stage header carries its own numbered Run pill; and all shared components now live in one stylesheet, assets/css/phf-ui.css. No change to any build, merge, validation, output file, download, storage or Library behaviour.

## Commit notes (by task)
- Task 1 — rail uploads: the one-letter-per-line wrapping came from the Drop-All assignment rows (.bulk-row) moving into the 300 px rail in v21.26.0 with a grid that let the select + Assign button crush the name column. Fixed at the root in phf-ui.css (status · name grid, name on one line with ellipsis and a full-name tooltip, controls non-shrinking, the note on its own short line with a "▸ details" fold). Status words: ASSIGNED → READY (green), replacement → UPDATED (green), needs a choice → REVIEW (amber), unrecognised / unreadable / invalid → INCOMPATIBLE (red); a required input not supplied stays the rail's REQUIRED row (neutral MISSING). Recognition, validation, manual assignment, replacement and removal are unchanged.
- Task 2 — output rows: each generated file is one line at desktop (tick · name · filename · meta · made-at · size · Download), size and Download right-aligned in fixed columns; two lines only below ~900 px. The per-group "Complete — … outputs ready" line is hidden once a stage is DONE for POS / CH2 / Unique (the header already shows DONE · n files); the Combined Master keeps its line because it carries the match-check summary. The #autoDownload repeat box is removed — the automatic download of the full merged master when the master finishes is unchanged, and the file remains in its row and in the top strip. Every file, warning and Download is kept.
- Task 3 — badges: one .phf-badge system — green only for READY / DONE, amber for REVIEW / WARNING, red for ERROR / INCOMPATIBLE, neutral for WAITING and plain counts ("0 FILES"). Panel heads and group headers put the badge immediately left of the chevron at a fixed right edge; the gap between collapsed panels is reduced.
- Task 4 + Task 11 — RUN strip: #dbRunStrip is now a direct child of <main>, above the two-column .builder-shell, full width, position: sticky at top 0 (the page header scrolls away). POS / CH2 / Unique / Master pills are <button>s that run buildStage(id); disabled until that stage's inputs are ready and while any build runs (lockRunControls); buildStage also refuses when prerequisites are missing. Actions grouped right: Build all databases · Full merged master · AV to Order · Clear session (destructive style; now asks for confirmation before reloading). Panels carry scroll-margin-top so anchored sections are not hidden under the strip.
- Task 5 — counts: the Databases panel badge reads "n FILES · m IN LIBRARY" (session outputs vs saved copies); Saved Files keeps its own count.
- Task 6 — merge sidebar: the "Storage protected" note and the "Saved vs session" paragraph are removed from the Input Files sidebar (markup only; storage protection, session persistence and Library loading are unchanged).
- Task 7 + Task 8 — merge stage pills: the top strip's three pills are buttons that call runTo(stage); each stage header has a compact numbered "① Run stage 1" pill on its right, before the chevron, wired to the same runTo, with propagation stopped so it never folds the header. The big "Run / update stage N" buttons are removed.
- Task 9 — shared CSS: new assets/css/phf-ui.css (run strip, step pills, action pills incl. ghost / destructive, badges, navy panel heads, database / stage group headers, one-line file rows, rail assignment rows, focus-visible rings), scoped to body.phf-page-db and built on the existing --phf-* tokens in theme.css. The duplicated blocks were deleted from tools/database-build/css/app.css and tools/pos-supplier-merge/css/merge.css; both tools link ../../assets/css/phf-ui.css after theme.css. No new framework; no new !important (the ten present are carried over where compact-layout.css already uses !important).
