# Staff Hub v21.32.0 — Library Add buttons back (A–P supplier files), steps row above the merge sheet, white Run / update buttons, Reconcile summary instead of step notes, previous-build files kept downloadable, UPDATED turns green after a re-run (20 Oct 2026 21:30 AEDT)

**Summary:** v21.32.0 — POS New Product Check Clean's Supplier Updates card again shows "Open the IN_SUPPLIER sheet" and "From the Library + Add CH2 / + Add Unique" on one row; each Add now takes the smaller A–P supplier-layout file Build POS Master saves (clean_…_pos_db), falling back to the full set. The merge sheet carries the same RUN 1 · 2 · 3 row as the top strip. Stage / step / database headers read status badge → white "Run / update" button → chevron in all three tools. Reconcile's step notes from v21.31.0 are removed; the intro at the top now gives a short summary with the Integrity Engine version and an engine-ready line. In Build POS Master, replacing an input no longer deletes the files already built — they stay in the table marked "Previous build · inputs updated" and still download until that database is rebuilt. Two existing faults are fixed: the full-set Add failed with "No matching column headings", and the POSActive "POS UPDATE (TXT)" button could hand over the INSERT file.

## Changes by item
- **Supplier Updates card (POS New Product Check Clean v1.21.0).** "Open the IN_SUPPLIER sheet ↓" (left) and "From the Library  + Add CH2 set · + Add Unique set" (right) sit on one row inside the card; they wrap only below ~1,180 px. The row is always shown: a button whose file is not in the Library yet is greyed with "not in the Library yet — build CH2 / Unique in Build POS Master Databases". Each button prefers the A–P supplier-layout file (clean_ch2_data_pos_db_… / clean_uhp_data_pos_db_… — the exact 16 columns the merge reads) and falls back to the full set when only that is saved; its small line says which ("9,682 rows · A–P supplier layout · built …" or "… · full set · …").
- **Build POS Master saves the A–P files (v21.21.0).** Building CH2 or Unique now also saves its supplier-layout file to the Library (new kinds lib:ch2-posdb / lib:uhp-posdb, "CH2 / Unique supplier layout (A–P)"). The full sets are still saved as before. The table labels the three supplier-layout rows "POS supplier layout", "CH2 supplier layout — used by POS New Product Check Clean (Add CH2)" and "Unique supplier layout — … (Add Unique)".
- **Fixed: full-set Add.** Since the full sets moved to spaced headings, "+ Add CH2 full set" failed with "Supplier_Data: No matching column headings were found." supplier-layout.js v1.1.1 and the merge tool's combined-master check now read spaced and underscored headings alike. Adding the A–P file and adding the full set give identical rows (tested: CH2 9,682 / 9,682, Unique 4,847 / 4,847).
- **Steps row above the merge sheet.** Above the IN_SUPPLIER / OUT_MERGED_DATA / … tabs: RUN · 1 Highlight + Best Buy · 2 Build OUT_MERGED_DATA · 3 Insert + Update & Export, with Run all stages and the POS TXT downloads on the right. They share state with the top strip (same pills, same disabled rules, same handlers), so the sheet can be run without scrolling up.
- **Fixed: POSActive TXT buttons.** The single "POS UPDATE (TXT)" button took the first TXT file, which could be the INSERT file. Each button now names the file it holds (POS UPDATE / POS INSERT; UPDATE first) and a second button appears when both files exist — in the top strip and the sheet's steps row.
- **Header buttons (screenshot 2).** Every stage / database / step header in the three tools reads status badge → white "Run / update stage N" / "Build / update …" / "Run / update step N" button → chevron (the v21.31.0 order rule that put the button first is removed from phf-ui.css).
- **Reconcile intro instead of step notes (Reconcile v2.16.0).** The v21.31.0 "What this does" / Needs / Checks-produces / Output lines, "How it works" folds, column previews and the Steps-panel version line are removed; step text is back to v2.14. The intro at the top reads "Reconcile a CH2 / supplier delivery against the POS back-end order. Runs the Integrity Engine (v2.6.38) in this browser: Check inputs, Reconcile …, then Export files … Everything runs locally; nothing is uploaded." with a green "Engine ready" pill — shown only when the spreadsheet reader, PDF reader, Excel writer, zip writer and the reconcile engine have all loaded (otherwise a red "Engine not ready" naming what is missing) — and a small line "Integrity Engine v2.6.38 · Reconcile v2.16.0 · PDF reader 3.11.174". The version comes from the engine's own build constant, not typed into the page.
- **Previous-build files stay downloadable (Build POS Master).** Replacing an input used to delete every generated file of the databases it feeds. Those rows now stay, shaded blue with ↻ and "Previous build · inputs updated", with a note above the table; Download still works. The top strip's Full merged master / AV to Order buttons get a blue outline and a "previous build" tooltip. Rebuilding that database replaces the rows with fresh green ones.
- **UPDATED → LOADED after a re-run (all three tools).** Build POS Master clears an input's blue UPDATED stage by stage — e.g. a new Brand list turns green once POS, CH2 and Unique (the databases it feeds) have been rebuilt. POS New Product Check Clean clears UPDATED when a stage run finishes. Reconcile clears it when a reconcile finishes.
